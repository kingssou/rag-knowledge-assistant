# 评估方法说明

## 为什么必须有评估集

RAG 项目的分水岭不在「能不能答」，而在「能不能证明答得好」。没有评估集，调 prompt、换分块策略、换检索权重都只能靠感觉。本项目把评估做成可重复执行的一等公民：`python main.py eval` 输出结构化报告。

## 评估集格式

`evaluation/qa_dataset.jsonl` 每行一条：

| 字段 | 含义 |
|---|---|
| id | 用例编号 |
| question | 用户问题 |
| relevant_sources | 应被召回的文档名列表，用于算检索指标 |
| reference | 标准答案，用于算生成指标 |
| should_refuse | 是否应当拒答，用于算拒答正确率 |

当前内置 10 条示例（9 条可答 + 1 条应拒答）。真实项目中应按业务文档扩充到 50-200 条，并覆盖：精确数字题、多跳推理题、同义改写题、越界问题、对抗性问题。

## 指标定义与局限

| 指标 | 定义 | 局限 |
|---|---|---|
| Recall@k | 前 k 个召回结果中命中相关文档的比例 | 只看文档级命中，不看具体段落 |
| Precision@k | 前 k 个结果去重后相关来源占比 | 单文档多分块时按来源去重，避免被人为压低 |
| MRR | 第一个命中相关文档的排名倒数 | 只关心第一个命中 |
| Faithfulness | 答案词在引用上下文中的覆盖率 | 词级近似，无法识别否定与语义等价 |
| Answer Relevancy | 答案与参考答案的词级 F1 | 依赖参考答案质量，对改写不友好 |
| Refusal Accuracy | 拒答判断与标注是否一致 | 阈值敏感，需结合置信度一起看 |

## 如何用它指导迭代

1. Recall 低：优先调分块大小、top_k、混合检索权重 alpha。
2. Faithfulness 低：优先改 prompt 约束、降低 temperature、加强拒答规则。
3. Relevancy 低但 Faithfulness 高：说明答案有依据但答非所问，检查问题理解和上下文注入。
4. 拒答正确率低：调整 `MIN_CONFIDENCE`，或增加「资料不足」类样本重新校准阈值。

每次调参后重跑评估，把 summary 记进实验记录，对比着看，不要凭单条问答下结论。
