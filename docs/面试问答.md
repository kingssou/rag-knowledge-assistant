# 面试常见追问与回答口径

## 1. 这个项目和你简历上的项目有什么不同？

简历上的项目是数仓和 AI 平台配置，这个项目是**手写代码的 AI 应用工程**：我自己实现了文档处理、混合检索、重排序、引用溯源、评估和部署全链路，不是拖拽式配置。它证明的是把模型接进业务系统的编码能力，而不是用过某个平台。

## 2. 为什么用混合检索，不用纯向量？

因为实际文档里大量关键信息是数字、编号和专有名词，纯向量对这类精确匹配不稳定；而 BM25 无法召回用词不同但语义相近的表述。所以向量负责语义，BM25 负责精确，归一化后加权融合，alpha 可调。

## 3. 分块怎么定的，为什么是这个大小？

默认 500 字符、80 重叠。优先按段落切，段落过长退到句子边界，最后才硬切。重叠是为了避免答案跨块被截断。这个值是起点不是终点，正式项目要用评估集扫参数，看 Recall@k 和 Faithfulness 的变化来定。

## 4. 怎么防止模型胡编？

三层约束：Prompt 里明确只允许依据资料作答；生成后解析引用编号，没有引用支撑的句子视为不可信；置信度低于阈值直接拒答。同时用 Faithfulness 指标持续监控。这三层都不完美，所以保留人工确认环节，高风险场景不直接面向终端用户。

## 5. 评估指标是怎么算的？说出定义和局限。

Recall@k、MRR 看检索；Faithfulness、Answer Relevancy 看生成；Refusal Accuracy 看拒答。当前是词级近似实现，不是 RAGAS 完整版——局限是不能识别语义等价和否定语义，所以只作横向对比和回归监控，不作绝对质量结论。这个边界要在回答里主动说清楚。

## 6. 如果让你上生产，还缺什么？

- 文档增量更新与删除的一致性（当前按来源重建）；
- 向量库换成支持分布式和过滤的 Milvus / Qdrant；
- 加入 query 改写、多轮对话与会话记忆；
- 引入 rerank 模型替代轻量规则；
- 完整的权限隔离与审计日志；
- 用真实业务评估集重新校准阈值，并做 A/B。

## 7. 为什么默认用 hash embedding 和 mock LLM？

为了让项目在无网络、无 Key、无显卡的环境也能跑通全链路并做确定性回归。这是工程上的可测性设计，不是效果最优配置。通过环境变量就能切到真实模型，适配器接口不变——这点恰恰说明设计是可替换的。

## 8. 你怎么看 AI 应用开发这个岗位？

模型能力是底座，工程能力才是分水岭：能不能把文档、检索、模型、评估、服务、部署串成可交付的系统，能不能用指标说明效果而不是凭感觉。我这个项目就是按这个思路做的。
