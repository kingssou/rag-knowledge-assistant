# 大模型技术应用说明

本项目不是「调一个模型的 Demo」，而是一个围绕大模型做工程化的 RAG 系统。下面按技术点说明大模型在本项目里具体怎么用、代码在哪、为什么这么设计。

## 一、模型接入层：统一的 LLM 适配器

代码：`generation/llm.py`

核心设计是 **OpenAI 兼容协议统一封装**。只要服务提供 `/chat/completions` 接口，就能通过同一个适配器接入：

| 模式 | 说明 | 环境变量 |
|---|---|---|
| `openai` | OpenAI 官方或任意兼容服务 | `LLM_MODE=openai` + `OPENAI_BASE_URL` + `API_KEY_ENV` |
| `ollama` | 本地私有化部署大模型 | `LLM_MODE=ollama` + `OLLAMA_MODEL` |
| 国产模型 | DeepSeek / 通义 / 智谱 / Moonshot 等 | 改 `OPENAI_BASE_URL` 指向其兼容端点 + 对应 Key |

关键点：**切换模型不改一行业务代码**，只改环境变量。这是 AI 应用工程里「模型可替换」的设计目标。

适配器统一暴露三个能力：
- `chat()`：标准对话补全
- `stream()`：流式输出
- `structured()`：结构化 JSON 输出

## 二、流式输出（Streaming）

代码：`generation/llm.py` 的 `stream()` + `api/server.py` 的 `/ask/stream`

大模型生成是逐 token 的，流式输出能显著降低首字延迟。项目用 FastAPI 的 `StreamingResponse` 把模型 token 逐个推给前端，而不是等整段生成完再返回。

```bash
curl -X POST http://127.0.0.1:8000/ask/stream \
  -H "Content-Type: application/json" \
  -d "{\"question\":\"住宿费标准是多少？\"}"
```

## 三、结构化输出（Structured Output）

代码：`generation/llm.py` 的 `structured()` + `api/server.py` 的 `/structured`

让大模型按约定的 JSON Schema 返回，是 Agent 工具调用和下游程序消费的前提。项目做了：
- 用 `response_format=json_object` 走原生 JSON 模式；
- 模型不支持时降级为文本解析；
- `_safe_json()` 处理 Markdown 代码围栏、前后缀杂质等常见问题。

对应接口 `/structured` 会让模型输出 `{answer, sources, ...}` 结构，可被程序直接读取。

## 四、上下文工程（Context Engineering）

代码：`generation/context.py`

这是 RAG 区别于「简单调模型」的核心工程点：

- **token 预算控制**：`estimate_tokens()` 估算 token（中文按字、英文按词近似），`fit_context()` 在预算内按相关度顺序保留检索片段，避免撑爆模型 context window；
- **多轮对话管理**：`Conversation` 只保留最近 N 轮（可配 `HISTORY_TURNS`），历史不无限膨胀；
- **相关性优先裁剪**：分数高的证据先保留，预算不够就丢弃低分片段。

生产环境应把 `estimate_tokens` 换成对应模型的 tokenizer（tiktoken / transformers），接口已经留好。

## 五、Prompt 工程与幻觉抑制

代码：`generation/prompts.py` + `generation/answer.py`

- System Prompt 明确约束「只能依据参考资料回答」「每个事实标注引用编号」「资料不足则拒答」；
- 生成后解析 `[n]` 引用标记，映射到真实来源文件（引用溯源）；
- 置信度低于阈值（`MIN_CONFIDENCE`）直接拒答，不调用模型编造；
- 用 Faithfulness 指标持续监控答案是否忠实于检索到的上下文。

## 六、Embedding 模型

代码：`retrieval/embedder.py`

提供三种 Embedding：
- `hash`：确定性哈希向量，离线可跑、结果可复现，用于测试；
- `sentence-transformers`：本地句向量模型（如 `all-MiniLM-L6-v2`），真正的语义向量；
- `openai`：OpenAI 兼容的 `/embeddings` 端点，可接支持该协议的云端服务。

生产环境用后两者，`hash` 只用于无网络环境跑通链路。

## 七、如何切换到真实大模型

**方案 A：本地私有化（Ollama）**
```bash
# 安装 Ollama 后
ollama pull qwen2.5:3b
set LLM_MODE=ollama
set OLLAMA_MODEL=qwen2.5:3b
set EMBED_MODEL=sentence-transformers
python main.py init --reset
python main.py serve
```

**方案 B：国产模型 API（以 DeepSeek 为例，其他兼容服务同理）**
```bash
set LLM_MODE=openai
set OPENAI_BASE_URL=https://api.deepseek.com/v1
set API_KEY_ENV=DEEPSEEK_API_KEY
set LLM_MODEL=deepseek-chat
set DEEPSEEK_API_KEY=你的key
python main.py serve
```

**方案 C：OpenAI**
```bash
set LLM_MODE=openai
set OPENAI_API_KEY=你的key
python main.py serve
```

切到真实模型后，README 里的截图会自动变成真实大模型生成的回答，无需改前端和业务流程。

## 八、当前 demo 模式的说明

默认 `hash + mock` 是为了让项目在**无 Key、无显卡、无网络**环境也能完整运行和回归测试，这是可测性设计，不代表项目不具备大模型能力。所有大模型的接入、流式、结构化、上下文工程代码都已实现，切配置即可启用真实模型。

面试时应当主动说明这一点，并演示如何切换——这恰恰体现对「模型可替换、工程可测试」的理解。
